# API publica v1

Respostas em JSON (`application/json; charset=UTF-8`, `Cache-Control: no-store`). Somente leitura.

## GET /api/v1/cadastro/disponibilidade

Verifica, durante o preenchimento do cadastro, se um valor ja esta em uso.

| Parametro | Valores |
| --- | --- |
| `campo` | `usuario`, `email` ou `cnpj` |
| `valor` | texto digitado (ate 200 caracteres; CNPJ com ou sem mascara) |

Resposta 200:

```json
{"campo":"email","valido":true,"disponivel":false,"mensagem":"Este e-mail já está cadastrado. Se a conta é sua, entre pelo login."}
```

- `valido=false` e `disponivel=null` quando o formato e invalido (nao consulta o banco).
- `usuario` e `email` comparam sem diferenciar maiusculas (collation da coluna); `cnpj` compara os 14 digitos.
- 422 para campo/valor invalidos, 429 acima de **60 consultas por IP a cada 5 minutos** (com `Retry-After`), 503 se o banco estiver indisponivel.
- E apenas orientacao: o cadastro deve revalidar no servidor e os indices `UNIQUE` (`uq_user_usuario`, `uq_user_email`, `uq_restaurantes_cnpj`) sao a garantia final.
- CPF nao e verificado em tempo real de proposito (LGPD: evitar descobrir se um CPF tem conta).

## GET /api/v1/restaurantes

Catalogo publico, somente restaurantes com `status_rest = 'ativo'`, ordenados por nome.

| Parametro | Descricao |
| --- | --- |
| `cursor` | opcional; valor de `proximo_cursor` da pagina anterior |
| `busca` | opcional; parte do nome (ate 80 caracteres) |

```json
{"itens":[{"nome":"Restaurante Modelo Cardapim","slug":"restaurante-modelo-cardapim","url":"/restaurante-modelo-cardapim","logo":null,"iniciais":"RM"}],"proximo_cursor":null}
```

- 12 itens por pagina; paginacao por cursor `(nome, id)`, estavel mesmo com novos cadastros.
- Nunca expoe CNPJ, telefone, e-mail, plano ou pagamento.
- 422 para cursor adulterado, 503 se o banco estiver indisponivel.
